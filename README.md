# Paradigm Clothing Projects

Storefront for the Paradigm Spring/Summer 2026 archive. Products and their images are stored in
**Neon PostgreSQL** and served by a small **Express** API. Styling uses the original page CSS plus **Tailwind CSS v4** utilities.

## Project layout

```
public/                 Frontend served by Express (index.html, Login.html, Signup.html, auth.js)
public/css/tailwind.css Generated by `npm run build` (git-ignored)
src/styles/tailwind.css Tailwind entry file
server/index.js         Express app (API + static files)
server/routes/products.js
server/db/schema.sql    products + product_images tables
server/data/products.js Seed catalogue (titles, prices, descriptions)
server/data/images/     Original product pictures used by the seed script
server/scripts/         migrate.js, seed.js
```

## Setup

Requires Node.js 20.12 or newer.

1. `npm install`
2. Create a Neon project, then copy `.env.example` to `.env` and paste the connection string into `DATABASE_URL`.
3. `npm run db:setup` creates the tables, converts every picture in `server/data/images/` to WebP
   (max 1600 px, quality 90), and upserts the products and image bytes into Neon. You can re-run it safely.
4. `npm run build` compiles Tailwind to `public/css/tailwind.css`.
5. `npm start`, then open http://localhost:3000 (`npm run dev` builds and restarts on file changes).

To add or edit a product, put the picture in `server/data/images/`, add or edit its entry in
`server/data/products.js`, and run `npm run db:seed` again.

## API

| Method | Path | Response |
| ------ | ---- | -------- |
| GET | `/api/health` | `{ "status": "ok" }` when the database is reachable |
| GET | `/api/products` | Array of `{ id, title, desc, price, image }` |
| GET | `/api/products/:id` | A single product |
| GET | `/api/products/:id/image` | Image bytes from the database. URLs include a content hash (`?v=`) so browsers cache them for a year |

## Tailwind notes

Tailwind's Preflight reset is not included because it would change the existing design (button fonts, heading sizes, images).
Each page keeps its CSS in `@layer components`, so Tailwind utilities override it the same way the old `style=""` attributes did.
Custom theme values (`text-accent`, `text-danger`, `text-alert`, and `font-mono` set to plain `monospace`) are in `src/styles/tailwind.css`.
