# Paradigm Clothing Projects

Storefront for the Paradigm Spring/Summer 2026 archive, live at https://prdgm.vercel.app.

- **Frontend** (`frontend/`): static HTML pages, styled with the original CSS plus Tailwind CSS v4 utilities.
- **Backend** (`backend/`): Express API on **Neon PostgreSQL**: products and photos, accounts, sessions, and orders.
- **Vercel**: serves `frontend/` from the CDN and runs the backend as one function (`api/index.js`).

## Project layout

```

frontend/admin.js         Owner console (only loaded for admin accounts)

frontend/css/tailwind.css Generated by `npm run build` (git-ignored)

backend/server.js         Local dev server (also serves frontend/)
backend/routes/           auth, orders, products, profile, wishlist, admin/ (products, orders, finance)
backend/lib/              password hashing (scrypt), sessions
backend/db/schema.sql     All tables (idempotent)
backend/data/products.js  Seed catalogue
backend/data/images/      The original t-shirt photos (never modified by any script)
backend/scripts/          migrate, seed, promote-admin
api/index.js              Vercel Function entry
vercel.json               Build command, output dir, /api rewrite
```

## Local setup

Requires Node.js 22+.

1. `npm install` (this also installs Tailwind locally; nothing to install globally)
2. Create `.env`: either `npx vercel link` then `npx vercel env pull .env`, or copy `.env.example` and paste your Neon URL.
3. `npm run db:setup` creates the tables and stores any missing t-shirt photos in Neon.
4. `npm run dev`, then open http://localhost:3000

## Deploying (Vercel)

Pushing to GitHub deploys automatically. Each build runs `npm run vercel-build`:
Tailwind build, then database migration, then photo seeding. The seed only adds products or photos that are missing.
It never overwrites existing ones and never restores products the admin deleted.
The database URL comes from the Neon integration's `DATABASE_URL` (or `POSTGRES_URL`).

## Owner (admin) account

1. Sign up on the site with your owner email.
2. Locally, with `.env` set: `npm run admin:promote -- you@example.com`
3. Log out and back in. (`-- you@example.com --demote` reverts it.)

## Security notes

- Passwords are hashed with scrypt (Node built-in). Only a SHA-256 hash of each session token is stored.
- Session cookies are `HttpOnly`, `Secure` on Vercel, and `SameSite=Lax`, and they expire after 30 days.
- Old accounts saved in browsers' localStorage by the previous version are deleted automatically and can't be migrated,
  because they were never on a server. Users need to sign up again.

## Tailwind notes

Tailwind's Preflight reset is not included because it would change the existing design. Each page keeps its CSS in
`@layer components`, so Tailwind utilities override it the same way inline styles did. Theme values (`text-accent`,
`text-danger`, `text-alert`, `font-mono`) are in `frontend/styles/tailwind.css`.

## Store features (Batch 5)

- Guests can browse. Logging in is only needed to check out, save a wishlist, review or request a restock.
- Sizes, colours and stock per item, with pre-orders, drop countdowns, sale prices, badges and extra photos.
- Checkout prices the cart on the server: stock, discount codes, bundle deal and shipping fee.
  Payment is Cash on Delivery until a gateway is added.
- Owner console: arrange, returns, customers, stock alerts, discount codes, inbox, store settings, CSV exports.
- Edit the size-guide measurements in `SIZE_GUIDE` at the top of `frontend/shop.js`.
- Vercel Analytics: enable it once under Project → Analytics. `frontend/analytics.js` only loads on vercel.app.

## Email & payments (Batch 4)

Both are optional: without the keys, emails are skipped and checkout offers Cash on Delivery only.
Store Settings → Integrations in the owner console shows what's connected. All variables are listed in `.env.example`.

- **Resend:** `RESEND_API_KEY`, `EMAIL_FROM` (a verified domain), `EMAIL_REPLY_TO`.
- **PayMongo:** `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET`. Create a webhook for `https://prdgm.vercel.app/api/payments/webhook`
  with the event `checkout_session.payment.paid`.
- **Also set:** `APP_URL`, `ADMIN_EMAILS`, `APP_SECRET`, `CRON_SECRET`.
